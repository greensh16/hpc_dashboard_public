TOOLS FOR RESEARCH COMPUTING

Know what your jobs actually used.

HPC Dashboard turns job telemetry into a clear account of where your CPU time, memory, storage and GPUs went. Inspect a run while it is active, or return to it when you are planning the next one.

TWO TOOLS, ONE WORKFLOW

Measure the job.
Read the evidence.

logger-rs collects resource use inside a job. Its current release has been tested on PBS/Gadi and Slurm/Setonix. HPC Dashboard reads the resulting files over SSH or from a local mount. There is no cluster-side service or database to maintain.

01

Collect with logger-rs

Add the shell library to your job script and mark the part of the workload you want measured. The collector writes telemetry to shared storage.

Meet logger-rs ↗
02

Explore in HPC Dashboard

Open a running or completed job to inspect CPU, memory, disk, network and GPU data by node and over time.

GETTING STARTED

Start with a job script you already have.

On Gadi, the logger is available as a shared module. Add two commands around the part of the job you want to study, then point the desktop app at the resulting logs.

Read the setup guide ↗
job.pbsPBS / Gadi example
module use /g/data/gb02/modules
module load logger-rs
source logger-rs.sh

telemetry_start
mpirun -np "$PBS_NCPUS" ./my_model
telemetry_stop

Module paths and storage directives depend on your site.
