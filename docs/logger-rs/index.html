THE COLLECTOR

A record of what happened inside the job.

logger-rs samples resource use from a job's cgroup and writes telemetry files that HPC Dashboard can read. It collects data on each node and brings multi-node results together without a daemon or database.

Get logger-rs ↓Read the documentation ↗

Linux x86-64 · tested on PBS/Gadi and Slurm/Setonix

job.pbsMark the work to measure
module use /g/data/gb02/modules
module load logger-rs
source logger-rs.sh

telemetry_start
mpirun -np "$PBS_NCPUS" ./my_model
telemetry_stop

Example for Gadi; module paths vary by site.

WHY USE IT

Measure the computation, not the staging.

Put telemetry_start and telemetry_stop around the part of your job that matters. That keeps setup and data transfers from distorting the figures you use to evaluate the workload.

01

Resource data by node

Follow CPU, memory, disk, network and available GPU measurements through the run.

02

Files your dashboard can open

Telemetry is written to storage you control and can be read over SSH or a local mount.

03

Designed to stay out of the way

Instrumentation problems are reported without failing the scientific job.

INSTALL AND DOWNLOAD

Use the module or deploy the package.

ON GADI

Load the shared module

There is no personal install step. Add the module path in your PBS script, load logger-rs and source the shell library.

module use /g/data/gb02/modules
module load logger-rs
source logger-rs.sh

Deployment guide ↗

The release package targets Linux x86-64. Slurm collection has been validated on Setonix; other Slurm sites still need validation. Run logger-rs --check inside an allocation to see which metrics are available. Other platforms can build from source; telemetry collection requires Linux cgroups.
